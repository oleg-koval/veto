# Veto v0.14: Jev Shadow Evaluation

## Goal

Add an experimental, disabled-by-default Jev shadow path that measures Jev
against Veto's authoritative sequential admission without allowing Jev to
select, reject, fail, or otherwise change a route. Establish the redacted data
contract and offline evaluator before adding any TypeSafe network client.

The work is stacked on the completed v0.13 decision-engine boundary. It must
remain fully usable without a TypeSafe account, API key, configuration, or
network access.

## Fixed design

```text
bounded shortlist -> ShadowingDecisionEngine -> sequential authority -> route
                         |
                         +-> Jev ShadowDecider -> redacted event dataset
                                                     |
execution outcome -----------------------------------+-> offline report
```

- `DecisionEngine` remains the authoritative routing contract.
- Jev implements a separate `ShadowDecider` contract whose result is evidence
  only and is structurally incapable of becoming the manager's outcome.
- The wrapper starts authority and shadow work concurrently, bounds shadow work
  with its own timeout, records the comparison, and returns the authority's
  exact outcome or error. Shadow failure is recorded but never returned as a
  routing failure.
- Persistence is an append-only, versioned JSONL event stream. Route events do
  not contain objective text, constraints, credentials, response bodies, or
  free-form model explanations. Later label events preserve unknown, known
  zero, and known nonzero measurements distinctly.
- Experimental enablement is explicit. Disabled mode does not read a TypeSafe
  key, instantiate an HTTP client, create a shadow file, or change legacy CLI
  output.
- TypeSafe API assumptions come from the live OpenAPI 0.2.0 read on 2026-09-23:
  bearer auth, `POST /v1/systemone`, named typed questions, choice confidence
  and probabilities, and token usage. The default model alias is `jev-latest`.
- The Jev request asks one candidate-selection choice (including a no-selection
  choice) and one success-probability yes/no question per candidate in the same
  call. Candidate names are encoded as opaque choice keys and mapped back
  locally.
- Reported cost is unknown unless an explicit price basis is supplied. API
  token usage is measured; a launch price is not represented as billed cost.

## Promotion policy v1

The v0.14 report may recommend v0.15 experimentation only when all gates are
evaluable and pass:

- at least 500 labeled shadow decisions across at least five task kinds, with
  at least 30 labels in every reported kind;
- the lower bound of a paired 95% confidence interval for Jev-minus-authority
  routing success is no worse than -2 percentage points overall and no reported
  kind is worse by more than 5 points;
- Jev selection confidence has Brier score no worse than the authority baseline
  and expected calibration error at most 0.05;
- Jev p95 decision latency is at most 750 ms and shadow unavailable/error rate
  is at most 1%;
- measured or explicitly based cost is known for at least 95% of samples and is
  no greater than 10% of sequential-admission decision cost;
- a simulated confidence/risk-aware hybrid requires fallback on at most 20% of
  samples while satisfying the routing-success gates;
- no raw objectives, credentials, provider response bodies, or free-form
  explanations are persisted, and tests observe zero shadow influence on the
  authoritative route.

These are conservative engineering gates, not claims about Jev or a promise to
enable v0.15 automatically. Passing produces `ready_for_opt_in_experiment`, not
automatic routing control.
